# Spec: Team Management

## Goal
Competing teams with named members are set up before the game starts and their state persists across page reloads so the gameshow can survive a browser refresh.

**Team count:** a gameshow runs with 0–4 teams (`GameshowConfig.teamCount`, default 2) — see
[team-count.md](team-count.md). This spec is written in terms of "team 1" and "team 2" because that
was the original design and is still the default; everything here applies per active team.

## Acceptance criteria
- [x] The entire team setup below is gated on the point system. When `pointSystemEnabled` is `false` the show has no teams, so `HomeScreen` renders neither the team overview nor the player list — just the title + a "Zum Starten klicken" prompt — and the gamemaster controls collapse to a single nav-forward. Advancing still works (empty-space click / arrow-space key / GM forward). See [point-system.md](point-system.md). All the criteria below assume `pointSystemEnabled` is `true`.
- [x] If `teamRandomizationEnabled` is `true`, `HomeScreen` shows the players of the hidden draw (see "Verdeckte Auslosung") plus a field to add names (comma-separated input adds several at once). There is no textarea of all names any more.
- [x] When the active gameshow has a configured roster (`GameshowConfig.players`, set in the admin Gameshows tab and exposed via `GET /api/settings` → `GlobalSettings.players`), that roster is **drawn on load** when the draw is empty, so the host only has to press "Teams zuweisen". An empty/absent roster starts with an empty draw.
- [x] On assignment, each player name is normalized so **every word** is capitalized (`"john smith"` → `"John Smith"`), not just the first — and every part of a double name (`"anna-lena"` → `"Anna-Lena"`) — see `assignTeams` in [GameContext.tsx](../src/context/GameContext.tsx). Applied on every path into the draw (show add field, GM add field, configured roster, reshuffle) — all go through [src/utils/teamDraw.ts](../src/utils/teamDraw.ts).
- [x] Names are shuffled then distributed **round-robin** over the active teams: player 1 → team 1,
      player 2 → team 2, … wrapping around. With the default two teams this is the historic
      alternation. See [team-count.md](team-count.md).
- [x] If `teamRandomizationEnabled` is `false`, `HomeScreen` is **not** auto-skipped — instead it shows the two-team overview in **manual mode**, where each team card renders its roster as an inline list of editable text inputs. Every member is editable in place (click a name to change it); **clearing a name's text and blurring removes that player**. Because teams were formed outside the show and are built by hand, each team card additionally renders one trailing blank "ghost" slot (the "+ Spieler hinzufügen" add-line) — typing a name into it appends that player; the same add/remove is also available on the **gamemaster** (a "Spieler hinzufügen" input per team plus a tap-to-remove member list). Teams may start empty. Edits are held in a local draft while typing (so a cleared field doesn't vanish mid-keystroke) and committed to the members-only `SET_TEAMS` action on blur (trim + drop empties); the draft re-syncs from state whenever the roster changes externally and no field is focused. Because everything routes through `SET_TEAMS`, edits sync live across show/GM/admin. The host advances to `/rules` via a click on empty space, an arrow/space keypress, or the gamemaster's forward control (team cards stop click propagation so editing never advances)
- [x] The same inline editable roster is shown in **random mode** after the teams are revealed (so names can be corrected/removed on the show); there it has **no** "+ Spieler hinzufügen" ghost slot — new players come from the GM's add field. The add-line is present **only** in manual mode (see above)
- [x] Team member lists are persisted to `localStorage` under the key of their team (`team1` … `team4`)
- [x] On reload, team members are restored from `localStorage` before any API call
- [x] Team names and members are displayed in the app header and on the `AdminScreen`
- [x] The `SummaryScreen` lists the winning (or, at one team, the only) team's members as a **balanced grid** rather than one name per line: `memberColumns()` picks 1 column up to 3 names, 2 up to 6, 3 up to 12 and 4 beyond that, rendered as `.winner-members[data-columns]` with content-sized columns so a long name widens the card instead of breaking mid-word; below 768px wide rosters fold back to 2 columns. The names step down in size as columns are added, the entrance stagger is per index (`animationDelay`, capped) instead of the four `nth-child` rules it replaces, and the card itself is `width: max-content` up to `min(1200px, 95vw)` with a `max-height` + scroll safety net. Nine names used to stack the fixed, viewport-centred card past both screen edges on a 1080p projector — the heading cut off at the top, the last names unreachable below.
- [x] Admin can edit team members directly on `AdminScreen` without going back to `HomeScreen`

### Verdeckte Auslosung (hidden draw, GM preview)
In random mode the draw no longer waits for "Teams zuweisen". It happens in the background, the gamemaster checks and fixes it on the phone, and "Teams zuweisen" only reveals it.

- [x] **The draw lives in the normal rosters** (`team1` … `team4`). A flag `TeamState.teamsRevealed` says whether the show may display them. So the draw is persisted to localStorage, synced over `gamemaster-team-state-v2` and protected by the rev guard like every other roster change. The rosters are the only list of names — there is no separate text field to keep in sync.
- [x] **Automatic draw on load.** As soon as the show start screen has its settings, random mode is on, teams are enabled, this is the active show tab (`!isInactiveShowTab()`) and the rosters are all empty, the configured `players` are drawn (Fisher-Yates + round-robin, see above). An inactive show tab never draws. A reload with a draw in place does not redraw and does not re-add configured players the GM removed.
- [x] **Hidden until revealed.** While `teamsRevealed` is false the show renders the players as an **alphabetical grid of names** (team order would give the draw away) with the player count, an add field ("Name hinzufügen" + "Hinzufügen") and "Teams zuweisen" — never the team cards. Each name has a ✕ to remove it, visible on hover/focus (always visible on touch screens). With no players the grid shows "Noch keine Spieler" and "Teams zuweisen" is disabled. Advancing to `/rules` (click, key, GM forward) is blocked until the reveal. With "Show-Buttons ausblenden" active the add field, the buttons and the ✕ are hidden; the name grid stays visible to the audience.
- [x] **Adding and removing names keeps the draw.** A new name (show add field or GM "Spieler hinzufügen") joins the currently smallest team (random tie-break); a removed name drops out; nobody else moves. Names match after normalization (every word capitalized) and as a multiset, so duplicate names work. When the configured `players` change at runtime before the reveal (admin Gameshows tab, live reload), the added names are placed and the dropped ones removed the same way.
- [x] **"Teams zuweisen" only reveals.** On the show and on the GM (`reveal-teams`) it sets `teamsRevealed` to true. It never shuffles. The show's button stops its click from bubbling: the reveal makes the screen advanceable, and React attaches the window "click to continue" listener while that same click is still on its way up — it used to fire and skip straight to the rules, so the audience never saw the teams.
- [x] **"Zuweisung verbergen" undoes the reveal.** After the reveal the GM start-screen controls carry a "Zuweisung verbergen" button (`hide-teams`). It sets `teamsRevealed` back to false, so the show returns to its first screen (the alphabetical player grid, add field and "Teams zuweisen") and advancing is blocked again. The draw itself is untouched — no redraw, no configured players re-added — so "Teams zuweisen" brings back exactly the same teams. It only exists on the start screen; to hide the teams after moving on, the GM first returns to "Startseite" via the Ablauf panel.
- [x] **GM preview.** In random mode the GM start-screen controls list every team (GM mirror order) as a **card** (`team` on the button group: the team's colour dot + accent edge) labelled `"<Teamname> (n)"`, holding one button per player in an **even grid** (`layout: 'grid'`, equal-width cells) with the names **alphabetical** within the team, so one is quick to find among 30+ (the button ids keep the roster index the commands address). From 768px the cards sit two per row. Before the reveal an info line reads "Vorschau – auf der Show noch verborgen. Spieler antippen zum Verschieben oder Entfernen.", followed by "Teams zuweisen" (`reveal-teams`, disabled while the draw is empty), "Neu mischen" and the "Spieler hinzufügen" input (`add-player`) — all **above** the team cards, so the GM never scrolls past a long list to reach them — and **no "Weiter"**: advancing does nothing before the reveal, so the button only competed with "Teams zuweisen". After the reveal the layout stays the same: "Zuweisung verbergen" takes the slot of "Teams zuweisen" at the top, followed by "Neu mischen" and "Spieler hinzufügen", then the team cards; below them the rename buttons ("Teamname ändern"), the optional "Teams tauschen" and "Weiter".
- [x] **Player popover on the GM.** Tapping a player opens a small popover next to that name (at every team count) with "→ ‹Teamname›" for every other team (`mvto-<from>-<index>-<to>`) and "Entfernen" (`rm-<team>-<index>`, the same command manual mode uses). Tapping an entry sends it and closes the popover; tapping outside, Escape or scrolling closes it without sending anything. Moving and removing work before and after the reveal.
- [x] **"Neu mischen" on the GM** (`reshuffle-teams`) redraws all players currently in the draw (the configured `players` when the draw is empty). It works before the reveal (the show stays hidden) and after it (the show's cards update live). It does not change `teamsRevealed`.
- [x] **Team cards with many players.** After the reveal (and in manual mode) each team card decides for itself, **by measuring** ([src/utils/rosterFit.ts](../src/utils/rosterFit.ts), run from a layout effect before paint): it shows **one column** of names as long as the page fits the screen without scrolling (the space below the cards counts too), and goes to **2 columns only when it would scroll otherwise** — the card with the most rows gets the extra column, since the cards of a row share one height, so a short card next to a long one keeps one column (3 when two still don't fit; at most 3 columns at 2 teams and 2 at 3–4 teams; below 1024px at most 2). One column and several **look the same**: every name sits in a pill, at the card's normal font size whatever the column count; only a name that does not fit its pill shrinks — that one name, on its own, in steps down to 50% — and an ellipsis is the last resort (an input can't wrap). Stacked or wrapped cards (phones, a 2×2 tablet grid) scroll anyway, so they keep one column. The fit is redone whenever the names, a team name, the team count or the window size change, and once the theme's web font has loaded. Cards keep the same height.
- [x] **Legacy state.** When `teamsRevealed` is missing (localStorage from an older version, or an older server cache value), it is derived as "any roster non-empty", so a show that was running before the update stays visible. The flag is persisted with every roster write, so a hidden draw is never re-derived as revealed.
- [x] `CLEAR_ALL` sets `teamsRevealed` back to false; `RESET_POINTS` leaves it (and the rosters) alone. A `SET_TEAM_STATE` payload without the flag keeps the local value.
- [x] Manual mode (`teamRandomizationEnabled: false`) ignores the flag: rosters are always shown, as before.

#### GM button menu (generic control capability)
- [x] `GamemasterButtonDef.menu?: GamemasterButtonDef[]` — a button with a `menu` does not send its own id; tapping it opens a popover anchored next to the button listing the menu entries, and tapping an entry sends that entry's id. The popover is portalled to `document.body` with a transparent backdrop, both carrying `data-gm-no-nav`, and raises `onOverlayActiveChange` while open, so neither a backdrop tap nor a key press advances the show behind it (see AGENTS.md, gamemaster run-of-show). It flips above the button when there is no room below and stays inside the viewport horizontally.

### Optional team names
- [x] Each team has an **optional** custom name. When unset (or blank), the app falls back to the positional label "Team 1" / "Team 2" everywhere — so shows that don't use the feature are unchanged.
- [x] The display name is computed at read time via `teamName(teams, 1 | 2)` in [src/utils/teamNames.ts](../src/utils/teamNames.ts) — never stored as derived state. Used everywhere a team is labelled: `Header`, `AwardPoints`, `SummaryScreen` (winner text), `CorrectAnswersTracker`, `GamemasterView` (joker cards), `HomeScreen` (team headings), `SessionTab` placeholders, the shared `BaseGameWrapper` award buttons, and the per-game scoring UIs (`BetQuiz` team/judgment, `Quizjagd` turn label, `FinalQuiz` bets + judging, `GuessingGame` tip labels/results, `WerKenntMehr` winner selection). Both the on-screen labels AND the labels sent to the gamemaster over the controls channel reflect the name.
- [x] Names are set by **click-to-edit**, not upfront text fields. On the `HomeScreen`, after teams are randomized, clicking a team heading turns it into an inline input (Enter/blur commits, Escape cancels); clicking the heading does not advance to the rules. On the **gamemaster**, after assignment the two team names render as buttons — tapping one swaps it for a rename input + "Speichern"/"Abbrechen". The admin `SessionTab` keeps its always-visible name fields (admin context).
- [x] Names live in the synced `TeamState`, so they persist to `localStorage` and propagate across all devices via the cached `gamemaster-team-state-v2` WS channel — no new endpoint.
- [x] A points/teams reset (`RESET_POINTS`) and a full clear (`CLEAR_ALL`) also clear the names back to the default labels.
- [x] In the `Header`, a long custom name first **shrinks its font a little** (the `TeamHeaderName` component steps it down through `[1, 0.92, 0.84, 0.76]` em until it fits, floored so it stays readable) and then truncates with an ellipsis (`.team-header-name`), while the score (": N Punkte", `.team-header-score`) and the joker grid always stay fully visible — the team pill never overflows its column. This holds at **every team count**: at 3–4 teams a pill is capped to half its side's line (see [header.md](header.md)), so a name can never push the side's other pill onto a second row — it is cut inside the pill exactly as at two teams. The name is re-fitted whenever the room for it changes: the fitter observes the name span itself as well as its label (a score growing to two digits narrows only the span) and re-runs once the theme's web font has loaded. The full name stays on the team cards and in every input.
- [x] On the `HomeScreen` team overview the **card heading** ([TeamCardName](../src/components/common/TeamCardName.tsx)) never widens its card, spills over its edge, or grows it taller: the heading is a box of exactly ONE line of the unshrunk heading size, pinned in px so every card in the row starts its roster at the same height whatever its own name did. A name too long for that box is **scaled down** to fit it — [useFitTeamName](../src/hooks/useFitTeamName.ts) steps the font through `[1, 0.86, 0.72, 0.6, 0.5, 0.4]` and stops at the first step whose wrapped text fits, then re-clamps the line count for the size that won (one line at full size, two at the half-size steps). A name that no longer fits even at the floor truncates with an ellipsis and is marked `data-name-clipped`, which switches it to `word-break: break-all`: with `overflow-wrap: anywhere` alone Chrome renders a truncated line as the bare ellipsis with the text dropped, which is how a long name used to vanish completely. The box is measured, not declared — a line box is as tall as the theme's font makes it — and re-measured when the card resizes or the theme's web font finishes loading. The colour dot is a flex SIBLING of the name, not inline content: inline, it ends up alone on the first line whenever the name is one long unbreakable word. The full name stays reachable — clicking the heading opens the inline input with the untruncated text.
- [x] With **three or four** cards sharing the row the heading size drops to `clamp(1.3rem, 3vw, 3.25rem)` (`#teams[data-team-count="3"|"4"] .team h2`) — and with it the one-line box, since it is measured from that size. Headings that are not the fitted card heading (e.g. the static ones in the theme showcase) keep the plain two-line clamp on `.team h2`, one line at three or four teams.
- [x] With **three or four** teams the `HomeScreen` uses the whole screen instead of the two-team layout's 1200px column: `#homeScreen:has(#teams[data-team-count="3"|"4"])` widens to `min(1700px, 92%)` (a strip of background stays on each side), the card grid moves up closer to the title, the card heading scales to `clamp(1.3rem, 3vw, 3.25rem)` and the member inputs to `clamp(1em, 2.3vw, 1.4em)` (relative to the `li`) with tighter row/input padding — so on a 1728px projector the four rosters fill the width with names about a third larger than before while a nine-player roster is no taller than it was. Two teams are unchanged.
- [x] **Where a name shows, it never overflows.** A custom name is free text and may be one long unbreakable word, so every surface that prints one either fits it or wraps it (mid-word if it has to) inside its own box: the header pill (shrink, then ellipsis — the ONE surface that cuts a name), the HomeScreen card heading (scaled to fit), the guessing-game tip fields and result cards, the award cards, the bet-quiz / wer-kennt-mehr team buttons (wrapping — they used to ellipsize, which left "Donaudampfsch…" with nothing saying which team), the final-quiz judgment headings, the quizjagd turn line, the "Führungswechsel" banner (capped to the header's width) and the summary's winner heading, plus the gamemaster's joker cards, score panels and control buttons (ellipsis or wrap in their columns). On every wrapping surface the colour dot is a **flex sibling** of the text, not inline content — inline, a long single-word name broke right after the dot and left it alone on the first line. Because nothing but the header cuts a name, the header's tightest box is the show's limit, and the hint below is the check for the whole show — not just for the header.
- [x] When a name would truncate on the header a **non-blocking** hint is shown at every entry point — the HomeScreen inline edit, the gamemaster rename panel (via an `info` control fed by the input's `emitOnChange`), and the admin SessionTab — the name is still accepted. `isTeamNameLong(name, jokerCount, teamCount)` measures **against an off-screen replica of the real header** built from the same tag, classes and **tree** as `Header.tsx` renders — the `.team-header-stack` columns above two teams, `data-team` + `id` on every cell, the colour dot before the name, `--joker-count` on the cell — so all the real (fluid) show CSS applies, including the 3–4 team pill cap and its joker-aware floor: it lays out the team pill (score + a joker grid with the right column count via `jokerColumns(count)`, which mirrors the TeamJokers grid 1→1/2→2/3→3/4→2/5→3/6→3; the grid leaves the tree when no jokers are enabled, as `TeamJokers` renders nothing then) and checks whether the name's content width exceeds its allocated box **at the smallest font the header shrinks to** (`NAME_MIN_FONT_SCALE = 0.76`, matching `TeamHeaderName`). A unit test diffs the replica's structure against the real `<Header>` at 2/3/4 teams with and without jokers, so the two cannot drift apart again. The replica is laid out at the **current display width** (no pinned dimensions) — so it predicts truncation for the screen the name is actually shown/edited on (the primary flow is click-to-edit on the show itself). The replica score uses a 2-digit value (`88`) so a name flagged OK still fits once points reach double digits, and its game counter reads the **widest** `Spiel k von N` (k = 1…N) the show will reach for its real length (`GlobalSettings.totalGames`, served by `GET /api/settings`) — the counter's width is room the names do not get, a fixed two-digit worst case flagged names the real header showed in full, and in a handwriting font `Spiel 5 von 5` is ~35px wider than `Spiel 1 von 5` at 1920, so the widest game of THIS show is measured rather than any one of them; `12` is the fallback when the length is unknown. There is **no hardcoded character/width budget**. Returns false (no warning) when measurement isn't possible: SSR / no layout (jsdom), or before the theme web font has loaded (`document.fonts.status !== 'loaded'`) — fallback-font metrics would misjudge widths. Components therefore call it through [useTeamNameCheck](../src/hooks/useTeamNameCheck.ts), which re-renders once `document.fonts.ready` resolves: in the admin the show's font is used nowhere else, so the first measurement is what starts its download, and without the re-render every later check in that cycle said false and the hint never appeared — and **below two teams**, where the header prints no name (`hasNamedTeams`). **Every** caller passes a `TeamNameFitContext` with the enabled-joker count AND the active team count (the gamemaster panel used to measure at the two-team layout in a four-team show) and the show length; the admin additionally passes the **show's theme** (`useTheme().theme`), which the replica pins on its off-screen wrapper as `data-theme` — the admin's `<html>` carries the admin theme, whose font is not the show's, so an unpinned replica flagged different names than the show did. The hint copy is the one string from `teamNameLongHint(jokerCount)`, which appends "(mit N Joker[n] weniger Platz)" when any are enabled. See [src/utils/teamNames.ts](../src/utils/teamNames.ts).

## State / data changes
- `AppState.teams.team1: string[]` … `team4: string[]` — member names per team (`team3`/`team4`
  optional; read through `teamRoster` in [src/utils/teams.ts](../src/utils/teams.ts))
- `AppState.teams.team1Name?: string` … `team4Name?: string` — optional custom name per team
- `AppState.teams.team1Points: number` — see point-system spec
- `AppState.teams.team2Points: number` — see point-system spec
- `AppState.teams.teamsRevealed?: boolean` — whether the show may display a random-mode draw (see "Verdeckte Auslosung")
- Actions: `SET_TEAMS`, `SET_TEAM_STATE`, `SET_TEAM_NAMES`, `SET_TEAMS_REVEALED`
- Context API: `assignTeams(names)` (full reshuffle, leaves the flag), `reconcileTeamDraw(names)` (incremental add/remove), `revealTeams()`. The pure draw logic (draw, reconcile, move, remove) lives in [src/utils/teamDraw.ts](../src/utils/teamDraw.ts)
- localStorage keys: `team1` (JSON array), `team2` (JSON array), `team1Name` (string, omitted when blank), `team2Name` (string, omitted when blank), `teamsRevealed` (`"true"`/`"false"`)
- Config flag: `teamRandomizationEnabled: boolean` in `config.json`
- `GlobalSettings.players: string[]` — the active gameshow's roster (`GameshowConfig.players`), served by `GET /api/settings`; drawn into the hidden draw when it is empty

## UI behaviour
- `HomeScreen` (`/`), random mode: alphabetical grid of the players in the hidden draw (✕ to remove), "Name hinzufügen" field, "Teams zuweisen"
- "Teams zuweisen": `SET_TEAMS_REVEALED` shows the drawn teams. Advancing goes to `/rules`
- Gamemaster: preview of the draw, player popover (move / remove), "Spieler hinzufügen", "Neu mischen", "Teams zuweisen" (see "Verdeckte Auslosung")
- `Header`: displays each team's name (or fallback) alongside current point totals
- `AdminScreen` (`SessionTab`): editable fields for each team's name + member list

## Related
- **Per-team colours** — the operator picks a colour per team in the admin Konfiguration tab; when enabled it marks every team surface with an accent edge plus a dot beside the name. See [team-colors.md](team-colors.md).
- **Team display order & gamemaster mirror** — which team sits on the frontend's left is operator-controllable (`TeamState.orderSwapped`, action `SET_TEAM_ORDER`), and the gamemaster screen always shows the mirror. See [team-order-mirror.md](team-order-mirror.md).

## Out of scope
- More than four teams (0–4 are supported — see [team-count.md](team-count.md))
- Per-team avatars or images (per-team *colours* are their own feature — see [team-colors.md](team-colors.md))
- Predefining team names in `config.json` (names live only in the live team state)
- Fixing players to teams before the draw (moving happens after it, on the GM)
- A preview or move UI in the admin PWA (the admin Session tab can still edit rosters as text)
